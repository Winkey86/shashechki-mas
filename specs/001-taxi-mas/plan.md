# Implementation Plan: визуальная МАС такси «Шашечки»

**Branch**: `spec/taxi-mas` | **Date**: 2026-10-31 | **Spec**: [spec.md](spec.md)

**Input**: принятая [постановка](postanovka.md), 52 требования спецификации.
Это план будущей реализации; готовность приложения и результаты опытов не заявляются.

## Summary

Одна локальная симуляция покрывает четыре лабораторные: формальная модель, сравнение
распределения, переговоры с тарифами и репутацией, парные испытания F1–F7. Последовательное
Python-ядро рассчитывает опыт; CLI и веб-сервер вызывают одинаковые функции. Интерфейс
показывает сохранённую трассу на условной карте, связывая агентов, цены, сообщения и показатели.
Четыре отчёта опираются на сохранённые результаты.

## Technical Context

**Language/Version**: Python 3.12+; установлен Python 3.14.3. JS ES modules, HTML5, CSS, SVG.
Совместимость с Python 3.12 проверяется отдельно при наличии интерпретатора.

**Primary Dependencies**: стандартная библиотека (dataclasses, enum, heapq, fractions,
random, json, csv, hashlib, argparse, http.server, threading, queue, pathlib, zipfile,
unittest). Локальный IBM Plex Sans с лицензией из design/fonts. Рабочее приложение
не требует npm, сторонних Python-библиотек и скачивания build-инструментов.

**Storage**: JSON/JSONL/CSV, ZIP; неизменяемые `results/<result_id>/` с манифестом и SHA-256.
Рабочие результаты игнорируются Git; отобранные доказательства сдачи находятся в `evidence/`.
Исходники и документы хранятся в локальном Git.

**Testing**: unittest (unit/contract/integration), фиксированные сцены, парные прогоны,
каноническое сравнение. Визуальная проверка работающего UI на 1440/768/390, клавиатура,
уменьшение движения, единая позиция панелей. Макет не заменяет проверки приложения.

**Target Platform**: локальные macOS/Linux с Python 3.12+ и современным браузером с
ES modules/SVG. Windows не входит в первую приёмку. HTTP только на 127.0.0.1.

**Project Type**: Python-пакет/CLI и локальный исследовательский веб-инструмент.

**Performance Goals**: пауза/шаг ≤200 мс на сцене 10 водителей после загрузки трассы;
последовательный опрос задания около 500 мс. Это проверяемые цели, а не измеренные факты.

**Constraints**: без внешних аккаунтов/моделей/платежей/корпоративных сервисов;
один worker и два ожидающих задания; точные деньги; независимость модели от wall-clock/кадров.

**Scale/Scope**: 10 водителей, 100 заказов, минимум 10 парных потоков на условие.
Пределы: 24 модельных часа, 1 000 000 событий, 100 000 событий в очереди. Достижение
предела — limit_reached. HTTP JSON ≤2 МиБ, пакет входов на диске ≤50 МиБ; увеличение
масштаба и лимитов обосновывается пилотом.

### Границы модулей

`domain` задаёт типы без I/O; `engine` владеет временем и очередью. `agents` получает
локальное представление и выдаёт намерения/сообщения. `protocol` применяет разрешённые
переходы. `pricing`/`reputation` не знают об HTTP. `allocation`/`negotiation` используют
общие фильтры/оценку; `faults` вносит воздействия. `experiments` материализует входы
и вызывает ядро; `artifacts` записывает результаты; `projection` формирует просмотр.
`cli`/`jobs`/`server` — адаптеры. JS не содержит второго ядра.

### Исполнение

Один worker последовательно выполняет задания. Автономность агентов определяется разделением
знаний и решений, а не системными потоками. Реестр и принятие отмены атомарны. Успех задания
означает расчёт и сохранение, а не успешную поездку каждого пассажира. Пауза относится к
просмотру; отмена расчёта сохраняет неполный результат. После перезапуска незавершённое
задание получает failed/INTERRUPTED; автоматического продолжения нет.

### Визуальная реализация

Рабочий frontend создаётся в `web/`; `design/interface.html` остаётся референсом.
Используется утверждённое направление framed-sheet: белая область, нейтральные границы,
IBM Plex Sans, акцент такси. Шесть связанных представлений: карта, участники, стоимость,
переговоры, результаты, отказы. SVG разделяет улицы, путь, агентов и сообщения. Локальные
знания отделены от глобального наблюдения. HTML-список обеспечивает доступ к объектам
клавиатурой; на узком экране панели идут последовательно. Один курсор event_seq;
checkpoint каждые 100 содержательных изменений представления, между ними — присваивания полей, без повторного расчёта решений.

### Инкременты после принятия этапов 5 и 6

1. Структура и контракт типов; US1 — модель, схемы, отчёт №1 до кода ядра.
2. US2 — обычная поездка, согласия, CLI/HTTP, карта и просмотр: функциональный MVP.
3. US3 — второе распределение, серии, показатели, отчёт №2.
4. US4 — конфликт, встречная цена, смена тарифа, репутация, отчёт №3.
5. US5 — семь воздействий, защиты, повторные опыты, отчёт №4.
6. US6 — воспроизводимость, доказательства, полный комплект и сквозная проверка.

US1 проверяется как отдельный учебный документ. US3–US5 используют базовую поездку;
их headless-проверка не зависит от полной визуальной оболочки. Числа в отчётах появляются после опытов.

## Validation Strategy

Денежные границы/рейтинг → сроки/согласия/инварианты → распределение/торг → F1–F7 →
парность/артефакты. Контракты проверяют CLI/HTTP, повтор команды, очередь, отмену,
ошибки записи, повреждённые данные и несовместимую схему. UI проверяется на нормальной,
конфликтной и аварийной трассах; отдельно измеряется пауза/шаг. Все SC имеют задачи.
Тестовый и рабочий код появятся на этапе реализации.

## Risks & Limits

| Риск | Мера / пересмотр |
| --- | --- |
| Тяжёлая трасса | Снимки/изменения, ограниченный объём; SC-010 до роста масштаба |
| Фоновый поток конкурирует за CPU | Пилот, затем оптимизация; процесс только по измеренному нарушению |
| Различия генератора Python | Повторять материализованные входы, сохранять версии |
| Веса/стратегии предопределяют вывод | Публиковать параметры, менять один фактор, допускать отсутствие эффекта |
| Правдоподобная ложь | Фиксировать пределы наблюдаемости |
| Остановка при записи | Манифест последним, неполный статус, без перезаписи |
| Сроки PDF без года | Уточнить календарь отдельно |
