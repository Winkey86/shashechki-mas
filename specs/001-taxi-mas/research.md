# Research: проектные решения для «Шашечек»

Дата: 2026-10-31. Вход: [spec.md](spec.md), [постановка](postanovka.md),
[конституция](../../.specify/memory/constitution.md). Две исследовательские подзадачи
speckit-plan проверили ядро и визуальный интерфейс. Это проектирование, не прогон модели.
Неразрешённых технических вопросов после исследования нет.

## R1. Последовательное ядро

**Решение:** Python 3.12+, стандартная библиотека; очередь heapq
`(time_ms, phase, seq, event)`, целые миллисекунды и метры. Уникальный seq стабилизирует
равные приоритеты. Обработчик атомарен; календарное время не влияет на решения.
Маршруты — Дейкстра по положительному времени рёбер; равенство — по длине, затем
лексикографически по последовательности идентификаторов рёбер.

**Обоснование:** стабильный счётчик предусмотрен [рекомендацией Python heapq](https://docs.python.org/3.12/library/heapq.html#priority-queue-implementation-notes).
Автономность определяется знаниями и решениями агентов, отдельные системные потоки ей не нужны.

**Альтернативы:** агентный фреймворк скрывает учебные механизмы; игровая физика и
многопоточная обработка увеличивают объём и неопределённость порядка.

## R2. Сроки и одновременность

**Решение:** фазы: 0 — воздействия/восстановление; 1 — движение/заявки;
2 — доставка; 3 — закрытие окна/раунда; 4 — истечение ожидания/назначения.
Ответ ровно в срок принимается до тайм-аута при актуальной версии. Новая отправка между
агентами имеет задержку минимум 1 мс; локальное применение выполняется внутри обработчика.
Нельзя добавить событие в уже пройденную фазу того же времени. Окончание раунда на границе
общего ожидания не продлевает срок подтверждения.

**Обоснование:** результат перестаёт зависеть от произвольного порядка таймеров.
**Альтернативы:** исключительная граница допустима, но менее естественна для своевременного
ответа; очередь только по времени оставляет ничьи неопределёнными.

## R3. Внешние входы и повторяемость

**Решение:** отдельные Random для заказов, характеристик, профиля связи и воздействий;
seed выводится SHA-256 из основного seed и метки. Внешние входы материализуются до опыта.
Профиль связи определяется каналом и временным интервалом, а не потреблением генератора.
Обычные стратегии детерминированы.

**Обоснование:** большее число сообщений не меняет следующие заказы. Для переносимого
повторения сохраняется пакет входов; генерация по seed фиксирует также Python и версию
генератора: межверсионная стабильность всех методов не гарантирована
([Python random](https://docs.python.org/3.12/library/random.html#notes-on-reproducibility)).

**Альтернативы:** общий генератор нарушает парность; одного seed недостаточно.

## R4. Точная экономика

**Решение:** денежные границы — целые копейки; промежуточные формулы, веса и рейтинг —
Fraction из целых чисел/проверенных десятичных строк, без float. Базовая и затем стартовая
стоимость округляются каждая один раз до копейки, половина от нуля (ROUND_HALF_UP).
Предложения уже выражены в копейках. Обязательство хранит снимок цены, тарифа и рейтинга.

**Обоснование:** точная дробь сохраняет произвольный знаменатель рейтинга; округление
только отображаемого рейтинга не меняет пороги. Основания:
[Fraction](https://docs.python.org/3.12/library/fractions.html),
[Decimal rounding](https://docs.python.org/3.12/library/decimal.html#rounding-modes).

**Альтернативы:** float непригоден для денежных границ; ограниченная точность Decimal
требует дополнительного правила деления рейтинга. Сторонняя числовая библиотека не нужна.

## R5. Распределение и переговоры

**Решение:** общий фильтр и `G=P+alpha*W+beta*(5-r_driver)`; P в копейках,
W в мс; alpha=1/60 коп./мс (10 руб./мин), beta=1000 коп./балл.
Центральный механизм использует доставленную телеметрию и публичное правило предложения;
аукцион — обязывающие предложения водителей. Скрытое состояние наблюдателя не подставляется.

Предварительный подъезд не является назначением. До трёх раундов по 2000 мс: первая
половина для предложений, вторая для ответов на встречную цену. Смена тарифа повышает
версию, расходует раунд, не продлевает срок. Подробности — [protocols.md](contracts/protocols.md).

**Обоснование:** пассажир действительно принимает решения. Сравнение с первым допустимым
предложением показывает цену дополнительного согласования.
**Альтернативы:** только минимальная цена игнорирует время и рейтинг водителя;
снижение чужой цены без согласия нарушает автономность.

## R6. Отказы без предписанного результата

**Решение:** F1–F7 задаются входами. Профили baseline/protected различаются опубликованными
проверками и восстановлением. Физические ограничения и проверенный реестр рейтинга не
отключаются для получения эффектного нарушения. Попытка, нарушение, предотвращение,
отсутствие эффекта, потеря обслуживания и восстановление различаются. Лимиты движка действуют всегда.

**Обоснование:** безопасная остановка не доказывает доступность; правдоподобная ложь без
независимого наблюдения может остаться невыявленной. Отсутствие улучшения допустимо.
**Альтернативы:** обязательная авария baseline и обещанный выигрыш подменяют исследование.

## R7. Локальная веб-оболочка

**Решение:** ThreadingHTTPServer на 127.0.0.1; один worker и queue.Queue(maxsize=2)
для ожидающих заданий. Серия — одно последовательное задание. Реестр защищён блокировкой,
отмена проверяется между событиями/прогонами. HTTP-обработчик не рассчитывает опыт.

**Обоснование:** короткие ответы, состояние, отмена; синхронизацию предоставляет
[queue](https://docs.python.org/3.12/library/queue.html). Стандартный сервер пригоден для
локального учебного инструмента; его ограничения описаны в
[Python http.server](https://docs.python.org/3.12/library/http.server.html).
Worker не обещает ускорение CPU-расчётов.

**Альтернативы:** долгий синхронный POST затрудняет отмену/повтор; FastAPI, БД,
WebSocket и пул процессов пока не оправданы. Выделение процесса рассматривается только
при измеренном нарушении отзывчивости после оптимизации просмотра.

## R8. Воспроизведение трассы

**Решение:** HTML/CSS, JS ES modules, SVG без сборщика. Python сохраняет снимки и
изменения представления. JS применяет записи, не рассчитывает цены или решения.
Все панели используют один курсор; просмотр доступен после завершения расчёта.

**Обоснование:** скорость/перемотка не меняют опыт. requestAnimationFrame интерполирует
только положение; скрытие вкладки ставит просмотр на паузу
([MDN](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame)).
HTML-список даёт клавиатурный эквивалент SVG; статусы озвучиваются без каждого кадра:
[W3C Keyboard](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html),
[W3C Status Messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html).

**Альтернативы:** второе ядро в браузере создаёт расхождения; потоковый показ ещё
рассчитываемой модели добавляет ненужную синхронизацию.

## R9. Идентичность и запись

**Решение:** case_id — хеш модельных условий; execution_id — уникальный экземпляр,
он же result_id одиночного опыта в API; серия имеет собственный result_id.
Каталог резервируется без перезаписи. Входы, трасса, метрики и просмотр записываются
до завершающего манифеста с SHA-256. Неполный результат явно обозначается.

**Обоснование:** технические поля отделяются от канонического содержания; NaN запрещён,
отсутствующее значение — null с причиной. Основания:
[Python JSON](https://docs.python.org/3.12/library/json.html),
[os.replace](https://docs.python.org/3.12/library/os.html#os.replace).
Атомарная замена файла не заменяет резервирование каталога.
**Альтернативы:** один ID условий и экземпляра приводит к перезаписи; один CSV без
входов и трассы не позволяет проверить вывод.

## Уточнения принятой постановки

Включительная граница срока, предварительный подъезд отдельно от обязательства, границы
округления, общий срок при смене тарифа и допустимость отсутствия эффекта защиты уточняют
реализацию в принятом объёме. Внешние сервисы, публикация и реализация на этом этапе не добавлены.
