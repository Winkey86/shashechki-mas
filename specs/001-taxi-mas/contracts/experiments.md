# Контракт экспериментов и показателей

Версия 1.0. Минимальная основная серия — 10 парных потоков по 100 заказов и 10 водителей
на каждое условие. Все условия, версии и веса публикуются; превосходство не предписано.

## Материализация потоков

Встроенный условный город содержит связный двунаправленный граф из сетки 5×5:
соседние узлы соединены рёбрами по 1000 м/120000 мс, стабильные ID строка/столбец/направление.
Это исследовательская геометрия, не оценка реальной дорожной ситуации. Недостижимость
проверяется отдельной сценой boundaries, где часть рёбер отсутствует; тесты создают из неё отдельные варианты входов без изменения сохранённых результатов.

Seeds 0–9. Для каждого seed создаются 100 пассажиров/заказов, 10 водителей.
Обычный интервал появления — равномерно 15000–45000 мс (целые), повышенная нагрузка —
5000–15000 мс. Origin/destination выбираются из разных узлов. Начальные позиции водителей
равномерны; первые 5 машин economy, остальные comfort. Бюджет равномерно 300.00–900.00 руб.
с шагом 1 руб.; max_wait=900000 мс; минимальный рейтинг водителя 4.0; допустимы оба тарифа,
начальный economy. Начальные фиксированные истории водителей: десять оценок 5;
пассажиров: три равные группы с десятью оценками 3,4,5 (для 100 участников: 34/33/33,
распределение по стабильным ID), плюс отдельные контрольные новые участники без истории.
Параметры водителя: стоимость 8 руб./км и 1 руб./мин, минимальная прибыль 30 руб.,
markup 0/10/20 руб. циклически по ID, decrement 10 руб. Ставки относятся к фактическому
движению; прибыль не включает неоговорённую плату за ожидание.

Независимые каналы генератора: orders, characteristics, communication, faults.
Профиль обычной связи: задержка 50 мс, без потерь/повторов. В условии delays для каждой
направленной пары ролей и 1000-мс интервала заранее выбирается задержка 500–2500 мс;
воздействия потерь/повторов включаются отдельными F3, а не незаметно в этом условии.
Канал выбирается по ролям sender/recipient и времени отправки; механизм не расходует общую
очередь случайных чисел. Seeds и версии не заменяют сохранённые массивы/профили.

## Матрица

| Серия | Варианты | Условия и неизменяемые факторы |
| --- | --- | --- |
| allocation | central / auction | normal, high_load, scarcity, delays; один механизм меняется, rating=off, conflict=first_acceptable, protection=protected |
| negotiation | first_acceptable / negotiation | Парные конфликты двух прибывших; обычный/тесный бюджет, равенство, отказ снизить, no agreement; rating=fixed, allocation фиксирован |
| rating | off / fixed | Один переговорный протокол, неизменные истории и входы; цена/обслуживание групп |
| faults | baseline / protected | По одному F1–F7 отдельно, те же входы/триггеры; затем при необходимости сочетания как отдельная серия |
| dynamic-reputation | fixed / dynamic | Дополнительная отделённая серия после основных; те же исходные истории, меняется только обновление после обязательств |

scarcity сохраняет 10 водителей и тот же спрос, но заранее заданная доступность первых
8 водителей отсутствует с 0 до 1800000 мс. Это дефицит доступных машин, не изменение числа
агентов. Основная allocation: 4×10×2=80 прогонов. Переговорные/рейтинговые основные серии
также используют 10 пакетов с 100 конфликтными заказами и 10 водителями; заказы создаются каждые
300000±5000 мс, пары водителей D0/D1, D2/D3, …, D8/D9 чередуются (повтор пары через 25 мин).
Точки конфликта — узел(0,0)→(0,1), 1 км/2 мин; машины исходно в(0,0), возврат к следующей
заявке выполняется обычным предварительным подъездом с учётом расходов, без телепортации.
За 25 мин пара успевает освободиться в штатном режиме; при отказах исход определяется моделью.
Предварительный подъезд по предложениям завершается до торгов, общий срок остаётся 900000 мс.
Конфликты обычного бюджета дополнены точными малыми граничными fixtures.
F1–F7 имеют по 10 парных малых опытов (140 прогонов) с заведомо активируемой целью;
not_triggered делает соответствующую пару неполной. Сочетания отказов не входят в обязательный минимум.

## Определения показателей

Показатель хранится как `{value,unit,reason}`. null обязателен при неопределимости;
нули допустимы только при известном нулевом результате.

| Показатель | Определение / единица |
| --- | --- |
| completed/cancelled/expired/failed/censored | Числа заказов по терминальному исходу либо нетерминальное состояние на горизонте; сумма равна числу входных заказов |
| service_rate | completed / все входные заказы; при 0 заказов null/NO_ORDERS |
| assignment_ms | От created до confirmed, только подтверждённые; отдельно число наблюдений |
| wait_ms | От created до boarding, только посаженные; незавершённые ожидания отдельно как censored |
| execution_ms | От created до completed, только завершённые; не смешивается с wall-clock |
| trip_ms | От boarding до completed, только завершённые |
| messages_sent/delivered/dropped/rejected | Счётчики конвертов; ретрансляция — новая отправка, дубликат доставки не новая отправка агента |
| bytes_sent | Размер канонического UTF-8 JSON конвертов при каждой отправке, без TCP/HTTP overhead |
| coordination_cost (RUB) | 1 коп./отправленный конверт + 1 коп./1000 байт (точная дробь) + 1 коп./решение агента; округлить итог до копейки |
| model_processing_ms | Сумма опубликованных длительностей обработки решений, по умолчанию 1 мс/решение; не CPU-время |
| wall_time_ms | Измерение perf_counter расчёта/сохранения раздельно, техническое поле, не canonical |
| final_price | Средняя согласованная цена завершённых поездок в RUB, строка с двумя знаками; отдельно число наблюдений |
| revenue/cost/profit | По каждому водителю и суммарно; выручка completed, затраты всей фактической подачи/поездки, прибыль может быть <0 |
| idle_ms | Сумма модельных интервалов доступного idle; offline не простой, предварительный подъезд — затрата движения |
| orders_per_driver | Завершённые заказы по стабильному множеству всех 10 водителей |
| Jain_revenue | `(sum x)^2/(n*sum x²)` по неотрицательной выручке всех водителей, включая нули; все нули → null/ALL_ZERO, n=0 → null/NO_DRIVERS |
| group_service_rate | completed/заказы в каждой фиксированной группе начального эффективного рейтинга (<4, 4–4.5, >4.5); пустая группа → null |
| violation_count | Число фактически нарушенных инвариантов по ID, отдельно attempts/prevented |
| detection/recovery_ms | От fault activation до диагностики/восстановления обслуживания; не было → null с причиной |
| availability_after_fault | Доля обслуженных затронутых заказов, отдельно safe_stop и resumed_service |

Решением считается одна запись выбора action_i после see_i/next_i, независимо от числа
порождаемых сообщений; чтение/отрисовка наблюдателя решением не считается.
Длительность обработки не блокирует движок календарным sleep. Результат решения применяется
как событие после processing_ms, затем сообщение получает транспортную задержку. Локальные
атомарные проверки commit/физики времени обработки повторно не добавляют. Денежный штраф
координации — условная исследовательская величина, не себестоимость реального сервиса.

## Агрегация и интерпретация

Для каждой пары сохраняются input_hash, условия, два result_id, оба значения и разность B−A.
Показываются все 10 значений, среднее и выборочное стандартное отклонение (n−1); n<2 —
null/INSUFFICIENT_PAIRS. Для производных средних показывается число наблюдений, не только итог.
Пропавшая/повреждённая/неактивированная пара не подменяется нулём; исключается с причиной.
Нельзя молча усреднять разные нагрузки или разные политики. Censored заказы не объявляются
отказами и не исчезают из знаменателя service_rate.

Сравнение меняет ровно указанный фактор; входы, стратегии, тарифы, веса, защита и горизонты
остаются равными, если они не являются исследуемым фактором. Фиксированная политика
рейтинга использует входную историю; dynamic обновляет историю только подтверждёнными
событиями и рассматривается отдельно. Десять повторов — исходный объём, достаточность
оценки и чувствительность к весам обсуждаются по пилоту без заранее заданного победителя.
Графики формируются из сохранённых таблиц; отсутствующие данные и остаточные ограничения видимы.

## Завершение опыта

`completed`: все входные заказы появились и терминальны, протоколы закрыты, конечные
доставки/воздействия обработаны. После разрешения спроса новые периодические TELEMETRY
не создаются; утратившие актуальность таймеры отменяются по версии. Конечные запоздалые
сообщения обрабатываются для проверки устаревания, без бесконечного продолжения телеметрии.
`horizon_reached`: достигнут горизонт с сохранёнными состояниями оставшихся заказов.
`limit_reached`: превышен предел обработанных/ожидающих событий. `cancelled`: принята
отмена задания, сохранённый частичный опыт не считается полным. Общие пределы не
объявляются нормальным завершением или доказанной защитой.

## Уточнения реализованной версии

В конфликтных сериях наценки выбираются seed-зависимо из 0/5/10/15/20 руб., задержка — 25–100 мс; все значения одинаковы внутри пары. Двадцать из 100 заявок negotiation исходно comfort с бюджетом 270 руб., поэтому сравнение включает согласованное снижение класса. Для цен дополнительно рассчитывается общая когорта завершённых заявок. Поток faults задаётся конфигурацией воздействий; отдельная случайная выборка не требуется. Денежные агрегаты хранятся строками RUB с HALF_UP; n_a/n_b — доступные наблюдения сторон, n — доступные парные разности. Восстановление определяется для F1/F6; service_preserved и resumed_service разделены.
