# Контракт протоколов агентов

Версия 1.0. Связан с [data-model](../data-model.md), FR-001–FR-032, FR-043–FR-045.

## Конверт и каналы

Каждый конверт содержит message_id, sender, recipient, kind, order_id, order_version,
sent_at_ms, deliver_at_ms, correlation_id, payload. Типы payload проверяются отдельно.
Повторная доставка сохраняет message_id. Время отправки и идентичность задаёт транспорт,
утверждения о позиции/цене могут быть недостоверными. Задержка ≥1 мс; профиль канала
определяется сохранённым временным интервалом. При дублировании используется фиксированное
число копий и смещение из профиля, потери фиксируются как события транспорта.

| Тип | Отправитель → получатель | Значимое содержимое |
| --- | --- | --- |
| REQUEST | пассажир → диспетчер | Точки, бюджет, ожидание, тарифы, min_driver_rating |
| TELEMETRY | водитель → диспетчер | Позиция/время наблюдения, доступность, класс, опубликованные параметры цены |
| SOLICIT | диспетчер → водитель | Версия, маршрут, тариф, сообщённый рейтинг, срок ответа |
| OFFER / WITHDRAW | водитель → диспетчер → пассажир и участники текущих торгов | offer_id, цена/срок/версия, ETA, рейтинг/простой с источником наблюдения либо причина выхода |
| COUNTER / COUNTER_REPLY | пассажир → диспетчер → водитель / обратно | Цена, версия, round_no; явное accept/reject |
| TARIFF_PROPOSE / TARIFF_REPLY | пассажир → диспетчер → водитель / обратно | Старый/новый тариф, совместимость, согласие |
| SELECT / CONSENT_REQUEST | пассажир → диспетчер / диспетчер → стороны | Выбранный offer; точные условия будущего commitment |
| CONSENT / DECLINE | стороны → диспетчер | Одинаковые order/version/driver/passenger/tariff/price, причина |
| CONFIRM / REVOKE | диспетчер → стороны | commitment_id, условия, срок подачи либо причина отзыва |
| ARRIVED / BOARD_REQUEST / COMPLETE | водитель/пассажир → диспетчер | commitment_id, подтверждаемое событие |
| STATUS / CANCEL | диспетчер → стороны / пассажир → диспетчер | Состояние/причина, актуальная версия |

Входящий конверт валидируется и заносится в локальный inbox атомарно при доставке;
processing_ms не откладывает его попадание в закрывающееся окно. Длительность относится
к новому решению action, после которого производится отправка. Ответ на границе окна
включается в набор выбора, но это не отменяет общий срок commit.

Сетевые ретрансляции считаются отдельными отправками. Прямые неразрешённые команды
водитель→реестр и пассажир→чужое обязательство отклоняются. В графе коммуникаций показываются
направления и виды сообщений, а не только соседство на дороге.

## Обычная поездка и подтверждение

1. Пассажир публикует REQUEST. Диспетчер проверяет входы/маршрут и запускает выбранное распределение.
2. Общий фильтр: допустимый тариф, класс, известная доступность, достижимость,
   рейтинг водителя ≥порог, подача ≤остаток ожидания, цена ≤бюджет.
3. Выбор отправляется сторонам. Водитель повторно проверяет собственную занятость и порог,
   пассажир — бюджет, срок и условия; оба отправляют явное CONSENT либо DECLINE.
4. Диспетчер атомарно проверяет согласия на одинаковую версию/цену/тариф, актуальность,
   уникальность заказа/водителя/пассажира. Только затем создаёт CONFIRM и резерв.
   Срок согласия — min(2000 мс, остаток ожидания). Просрочка не продлевает ожидание.
5. Подача и посадка требуют текущего commitment. Pickup deadline — min(wait_deadline,
   confirmed_at + согласованный ETA + 5000 мс). Посадка требует подтверждения пассажира.
6. COMPLETE проверяет достижение конца маршрута и текущую перевозку, единожды начисляет
   выручку и разрешённые репутационные события. Плата уже согласована.

Нет допустимых предложений/отказ: повторное распределение не более двух раз с увеличением
версии в пределах ожидания. При исчерпании — cancelled/expired с кодом причины.
Предварительный подъезд в конфликтной сцене не создаёт резерв или право посадки.
Объявленные цены ретранслируются участвующим водителям; их собственные пороги остаются
локальными. Экран наблюдателя может показывать порог, но это не расширяет знания диспетчера.

## Два механизма распределения

**central:** TELEMETRY в начале и каждые 5000 модельных мс, плюс изменение занятости;
кандидаты оцениваются по последним доставленным данным. Цена оценена по публичным
P_start/markup; неизвестный порог проверит водитель при CONSENT. Ожидание телеметрии
ограничено 2000 мс, затем оценка имеющихся сведений/отказ. Отказ кандидата позволяет
следующего по оценке в текущей версии, пока не истёк срок согласования; повторная рассылка
начинает новую ограниченную попытку.

**auction:** SOLICIT направляется известным водителям совместимого класса; водитель
сам вычисляет ETA, затраты, порог и обязывающую цену. Окно — 2000 мс в пределах ожидания.
После доставки всех своевременных OFFER выбирается минимум общей оценки.

Оценка `G=P+W/60+1000*(5-r_driver)` в копейках с точной дробью; при равенстве —
больший известный простой, затем меньший driver_id. Обе схемы имеют одинаковый фильтр,
параметры тарифов, стратегии водителей и согласия; различаются место вычисления/обмен.
Истинная позиция наблюдателя не исправляет молча устаревшую телеметрию.

## Конфликт и переговоры

Конфликтная сцена явно задаёт двух предварительно приехавших водителей. Расход подачи
обоих учитывается; обычное распределение не рассылает два окончательных назначения.

**first_acceptable:** первый доставленный допустимый OFFER выбирается сразу; сообщения
одного времени упорядочены общим seq. Проходит обычный протокол двух согласий.

Окно сбора не является сроком действия цены: стандартный expires_at предложения равен
wait_deadline; цена действует до него, отзыва или новой версии. Снижение замещает старое
предложение того же водителя, WITHDRAW отзывает его действующие предложения.

**negotiation:** максимум три раунда по 2000 мс, каждый обрезается общим wait_deadline.
Окно предложений — первая 1000 мс, ответы на контрцену — вторая 1000 мс.

1. В первом раунде водитель предлагает `max(floor,P_start+markup)`; далее уменьшает
   прошлую цену на decrement (по умолчанию 1000 коп.) до floor. При неизменяемой
   стратегии может сохранить цену; добровольный выход — WITHDRAW. Ниже floor не предлагает.
2. На закрытии окна предложений пассажир рассматривает все своевременные сообщения.
   Если бюджет B≥минимума тарифа, посылает единую контрцену
   `C=max(tariff_min,min(B,min(open_prices))-1000 коп.)`.
   При отсутствии предложений контрцена не формируется.
3. Водитель явно принимает C при `floor≤C≤собственная текущая цена`, актуальных версии,
   тарифе и доступности; иначе отклоняет. Молчание не считается согласием.
4. На закрытии окна ответов обрабатываются все своевременные ответы. Пассажир выбирает
   по G среди принятых контрцен и оставшихся допустимых предложений, затем SELECT и
   обычные согласия. Открытое предложение не исчезает из-за отказа от контрцены. Принятие C создаёт новый
   обязывающий offer_id с ссылкой на counter_id и замещает прежнюю цену этого водителя.
5. Если допустимого исхода нет, следующий раунд; отсутствие изменения условий при
   неизменных входах завершает торг раньше с NO_PROGRESS. После трёх — NO_AGREEMENT.

Смена comfort→economy возможна по инициативе пассажира, если все предложения выше бюджета
и economy допустим. Требуются явное согласие пассажира и минимум одного совместимого
водителя. Диспетчер увеличивает version, аннулирует офферы/согласия и собирает новые.
Смена расходует текущий раунд; число раундов и общий срок не сбрасываются.
Предложение тарифа содержит proposal_id и next_version=current+1; ответы ссылаются на него.
При фиксации диспетчер атомарно проверяет, что текущая версия ещё совпадает с исходной.
Согласие на тариф не означает согласия на цену/исполнителя. При равенстве действует
общий арбитраж G/простой/id. Принудительная продажа ниже порога не допускается.

## Воздействия и профили защиты

В обоих профилях действуют физическая связность, невозможность двойной физической посадки,
проверенный реестр и технические пределы движка. Baseline не обязан совершать нарушение.

| Воздействие | baseline | Дополнение protected | Проверка и остаточный предел |
| --- | --- | --- | --- |
| F1 исчезновение водителя до посадки | Нет повторного поиска, заказ ждёт общий срок | Pickup timeout, REVOKE/version+1, ≤2 переназначений | Старый водитель не восстанавливает назначение; после посадки поездка failed |
| F2 ложная позиция/ETA/цена | Принимается синтаксически допустимое утверждение до проверки согласия | Достижимость по последним наблюдениям, структура цены/тариф/версия | Правдоподобная ложь может пройти; необнаружимость фиксируется |
| F3 дубликат/старое сообщение | Повтор может вызвать лишний ответ/намерение | Дедупликация id, версия, допустимый переход | Единожды начисленные выручка/рейтинг всё равно не дублируются |
| F4 конфликт назначения/полномочий | Допускаются противоречивые намерения диспетчера | Атомарный commit с резервом, роль, сторона и версия | Попытка отдельно от фактического назначения/физической посадки |
| F5 изменённая цель/бесконечные действия | Только общий горизонт/предел движка ограничивает патологического агента | Ограничение раундов, окон, попыток, NO_PROGRESS | limit_reached не записывается как успешная защита |
| F6 недоступность диспетчера/маршрутизатора | Новые поездки не подтверждаются, ожидание до срока | Явный отказ средства, ограниченный повтор после восстановления | Уже подтверждённый путь может продолжаться; безопасная остановка ≠ обслуживание |
| F7 поддельная история/оценка | Проверенный реестр отклоняет изменение | Дополнительная проверка источника на входе, диагностическое событие | Отсутствие различия допустимо, нет требования ухудшить baseline |

Профиль — перечисленный набор переключателей, не скрытая замена алгоритма.
Все включённые проверки/пределы записываются в config. Сработавший fault хранит цель,
время, попытку, эффект и причинные trace_event_id; неактивировавшийся fault помечается
not_triggered и не считается успешной проверкой.
