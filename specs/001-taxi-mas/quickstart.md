# Quickstart: запуск и проверка реализации

Состояние на 2026-10-31: реализованы ядро, интерфейс и четыре исследования. Фактические проверки и идентификаторы результатов приведены в docs/verification.md и evidence/manifest.json.

## Подготовка

Python 3.12+ и браузер с ES modules/SVG; аккаунты, npm, LLM и сервер БД не требуются.
Открыть терминал в корне репозитория. Все команды ниже выполняются оттуда.

```sh
python3 --version
export PYTHONPATH="$PWD/src"
python3 -m unittest discover -s tests -v
python3 -m shashechki validate --scenario scenarios/normal.json
python3 -m shashechki serve --host 127.0.0.1 --port 8765 --output-root results
```

Открыть `http://127.0.0.1:8765`. При занятости порта выбрать другой через --port;
публичный host не поддерживается. Без сервера ES modules не обязаны работать через file://.
Выход сервера — Ctrl+C с фиксацией состояния текущих заданий. Ничего не публикуется.

| US1 | Сверить docs/model.md, три диаграммы, reports/lab-01.md с матрицей | Все характеристики трёх ролей, отдельные роль/связь, архитектура и ограничения |
| US2 | normal → запуск → выбрать пассажира/водителя → пауза/шаг/сброс/возврат/скорость | Одна согласованная поездка, одинаковый seq карты/цены/журнала; результат неизменен |
| US3 | allocation → central/auction → серия по четырём условиям | 80 прогонов, 10 пар на условие, одинаковые input_hash внутри пары, все заказы учтены |
| US4 | conflict и tariff-switch; затем negotiation и rating отдельно | Два приехавших водителя/пассажир, явная контрцена, ≤3 раундов, один commit, смена версии |

## Одиночный и повторный запуск

```sh
python3 -m shashechki run --scenario scenarios/normal.json --output-root results
python3 -m shashechki run --scenario scenarios/conflict.json --output-root results
python3 -m shashechki run --scenario scenarios/tariff-switch.json --output-root results
```

stdout каждой команды возвращает result_id/path. Для повторения подставить фактический
путь первого опыта; путь `results/RESULT_ID` ниже является обозначением, а не готовым ID.

```sh
python3 -m shashechki run --replay-inputs results/RESULT_ID --output-root results
python3 -m shashechki compare --left results/RESULT_ID --right results/REPEATED_ID
python3 -m shashechki export --result results/RESULT_ID --destination /tmp/shashechki-result.zip
```

compare должен дать exit0 и совпадение canonical; фактическое время не обязано совпадать.
Повтор экспорта в существующий файл отклоняется без изменения файла. Для нового экспорта
нужно новое имя, автоматического удаления не предусмотрено.

## Серии

```sh
python3 -m shashechki series --experiment scenarios/series/allocation.json --output-root results
python3 -m shashechki series --experiment scenarios/series/negotiation.json --output-root results
python3 -m shashechki series --experiment scenarios/series/rating.json --output-root results
python3 -m shashechki series --experiment scenarios/series/faults.json --output-root results
```

Проверить пары/число наблюдений/единицы/причины null и ссылки summary на исходные опыты.
Сводить условия отдельно. Динамическая репутация, если исследуется, запускается отдельной
командой с scenarios/series/dynamic-reputation.json; её выводы не смешиваются с fixed.

## Контрольные границы

- 5 км, 12 мин: economy 238.00, при рейтинге 3.50 старт 261.80, comfort 357.00.
  Рейтинг не меняет уже согласованную цену; промежуточные суммы не используют float.
- boundaries: нет заказов/водителей, неподходящий класс, недостижимый маршрут,
  бюджет ниже минимума, точная граница срока и оценки, все доходы 0, отрицательная прибыль.
- F1: исчезновение до посадки → отзыв/version+1; поздний возврат не сажает пассажира.
  После посадки отказ сохраняет фактическую позицию и незавершённую поездку.
- F3/F4/F7: дубликат, устаревшая версия, конфликт и подделка не дают повторной выручки,
  двойной физической посадки или поддельной истории. Отсутствие эффекта baseline допустимо.
- F5/F6: отличать защитное завершение от limit_reached, безопасную остановку от обслуживания.

## Контракт и ошибки оболочки

Проверить повтор request_id (то же тело → то же задание, другое →409), переполнение очереди
(503), неизвестное поле (422), повреждённый JSON (400), несовместимую схему,
отмену queued/running, перезапуск и ошибку записи/экспорта. Не использовать реальный
заполненный диск: отказ записи воспроизводится контролируемой тестовой заглушкой I/O.
Прерывание fetch не считается отменой расчёта. Проверки соответствуют
[interfaces.md](contracts/interfaces.md), а не предполагаемому поведению браузера.

## Визуальная приёмка

Сохранить снимки normal/conflict/fault на 1440×1000, 768×1024, 390×844 в evidence/visual.
На каждом размере проверить карту, участников, цену, переговоры, результаты и отказы,
отсутствие горизонтального переполнения страницы, подписи и видимый фокус.
Основные действия выполнить клавиатурой; включить prefers-reduced-motion.
При скрытии вкладки просмотр должен остановиться без скачка по возвращении.
На загруженной сцене playback-10 с 10 водителями измерить 20 действий пауза/шаг через browser performance
и отрисовку следующего кадра; максимальная задержка ≤200 мс. Сохранить браузер, ОС,
размер трассы и все значения; это локальный критерий, не обещание для любого устройства.
Повторить на двух скоростях и после изменения размера, сравнить метрики с CLI.

## Комплект сдачи

Четыре самостоятельных reports/lab-01.md…lab-04.md, исходники и инструкция отдельно,
приложение демонстрации с входами/конфигами/трассами/хешами/снимками.
В evidence/manifest.json связываются критерии и result_id с файлами. Все утверждения
о результатах имеют ссылки на реально выполненные опыты; неподтверждённые критерии
остаются открытыми. Сдача/публикация/отправка по почте выполняются по отдельной команде.
